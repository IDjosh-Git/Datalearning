# Teaching quality implementation and audit — 14 November 2026

## Source inventory

## Implemented changes
- Reused all original weekly examples, exercises, solutions, pitfalls, downloads, assessment pages, course URLs and progress hooks.
- Added a first-attempt teaching scaffold to the shared renderer for all 90 weeks: evidence of learning, task, progressive hint, check criteria, concealed answer, explanation of mistakes, transfer activity and verified in-page support steps.
- Moved advanced extension prompts to **after** the main practice and solution rather than showing them ahead of the task.
- Kept hint and solution in separate native `details`/`summary` elements, keyboard-operable without additional JavaScript. Added responsive and visible-focus styles to the existing canonical theme.
- Removed a calculated reading-time figure presented as a study-duration estimate; it was not a verified learner time estimate.
- Added `tests/teaching-quality-regression.mjs` to the academy suite to check nine courses, 90 complete weekly records, nine routes and presence/order of the shared teaching scaffold.

## Issues requiring further review
- A source-code presence test cannot confirm educational accuracy for every example, solution, quiz distractor or external dataset. A subject-matter review and actual tool execution against each relevant dataset is still needed.
- Some existing questions use predictable recall patterns; item-by-item assessment redesign and distractor review remain outstanding. Avoid assuming the shared scaffold fixes quiz validity.
- The generic hint intentionally does not reveal the answer but is not tailored to each of the 90 tasks. Course-specific hint authoring is recommended.
- Course-level prerequisites, verified time estimates, capstone reviewer/marking rules, certificate eligibility and tutor availability require owner confirmation. No new claims were added.
- Full browser accessibility audits, real mobile device checks, link/download HTTP checks, sign-in, cross-device cloud sync and instructor submission tests require staging credentials and a deployed environment.
- The existing source includes long, sometimes repetitive reading blocks. These were preserved to avoid removing valuable content without editorial review; further lesson-by-lesson restructuring is needed.

## Automated validation
`npm run verify:deployment` passed on Node 22.16.0, including build, lint, academy, security, practice arena, tutor and cloud-media tests. The project declares Node 24.x; retest in the target runtime. This is not a claim of production or learner testing.

## Recommended learner usability study
Ask first-time learners to locate a course, complete one weekly task before opening the solution, use the hint via keyboard, explain the expected result, recover from an incorrect answer, save and resume on a second device, and submit a sample capstone. Observe without coaching, then record task success, errors and confusion.
