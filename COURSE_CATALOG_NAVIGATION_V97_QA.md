# Course Catalog, Course Roadmaps and Learning Navigation — v97

## Scope and factual source

The v96 project was used as the baseline. The public catalog (`catalog.html`) has six entries sourced from the actual six course HTML pages and existing homepage course descriptions: Introduction to Data Analysis, Excel, SQL, Power BI, Python, and AI Integration. There are **58 trackable teaching units**: eight introduction lessons and ten weekly modules for each of the other five courses. The introduction's separate 12-question knowledge check remains available and is **not** counted as a ninth trackable unit. Unit titles, summaries, and known introductory minute estimates come from the real HTML. Weekly-module times are marked *self-paced* rather than being guessed. Activity, quiz, and resource badges appear only where an existing course module contains them. No new curriculum, grading, enrollment schema, API, or learner role was introduced.

## Implemented

- `catalog.html`: a dedicated, signed-out accessible catalog with course name, description, subject, level, published course duration, skill topics, preparation notes, and working course-detail links. Filter by typed keywords and the six actual subject groupings; reset and empty-result states included.
- Shared sidebar on the catalog, dashboard (`index.html`), and six course pages with Dashboard, All courses, My learning (account-gated), Reference library (account-gated), and the actual six course destinations. **Not included:** `/progress.html`, an administrator-only view. The desktop sidebar remains visible; on mobile it becomes a labelled, focus-trapped drawer with Escape, close control, focus restoration, and a backdrop. The original course-local week navigation remains in place.
- Existing course content remains in its original position. A compact overview and linkable roadmap were added after the native hero, including skills, actual lesson headings/outcomes, module sequence, existing activities and resources, and the next uncompleted lesson. A completed lesson link always remains available.
- The six original progress keys, introduction checkboxes, week-completion checkboxes, Supabase `course_progress` RLS, quiz code, and certificate requirements were retained. Course progress is shown for verified learners; signed-out visitors can read but cannot mark lessons complete. The next incomplete unit is labelled **Not started / Next up** rather than falsely called **In progress**: the existing schema only stores completion booleans, not a verified per-unit started state. Sync failures show that progress may reflect the current device rather than asserting that it was saved remotely.
- Removed the forced authentication overlay **only** from the public dashboard and six course browsing pages; the protected account, admin, instructor progress, and other routes retain existing authentication gates and server enforcement. On signed-out course pages, existing completion inputs are disabled. Each course provides a sign-in link carrying a URL-encoded intended path/hash; the unchanged `auth-flow.js` validates this return location and navigates back after successful login. The main dashboard and sign-in screen both link to the actual catalog.
- Added a theme switch to the shared sidebar and dual light/dark CSS rules; retained previous theme bootstrap. Added focus indicators, reduced-motion support, real progressbar semantics, mobile table containers and code overflow handling. The v96 stylesheet and all prior teaching resources are still present.

## Tests and evidence

- `node tests/catalog-navigation-v97.mjs`: passed; source pages, all six routes, all 58 target anchors, shell controls, passwordless browsing and completion hooks verified.
- `node tests/course-content.mjs`, `node tests/course-navigation-v22.mjs`, `node tests/visual-v96.mjs`, `node tests/visual-v95.mjs`, `node tests/auth-first.mjs`, and `node tests/auth-gate-runtime.mjs`: passed. The v95/v96 route checks now correctly evaluate their original **25-page legacy scope** separately from the newly added catalog; the auth coverage check accounts for intentionally public course browsing.
- Isolated Chromium component checks using the actual catalog and course HTML, v97 stylesheet, and JS: **16 combinations (eight public learning views × two widths, 390px and 1366px)**; no page-level horizontal overflow or JS exceptions, and all dynamic roadmaps populated. Mobile drawer toggling and Escape focus behavior, no-results and clear filters passed. Light/dark token rules checked statically.
- Simulated signed-in progress for the catalog and two representative courses with new / partially completed / completed records: nine scenarios passed. These used mocked authentication and progress services and **are not a live Supabase end-to-end test**.
- `npm test`: prior suite passes through `auth-gate-runtime.mjs` and then still stops at `tests/admin-roles.mjs` (`Role must be verified before page access`). This administrator-role failure existed in the supplied v96 baseline. The v97 implementation does not relax server-side admin access checks.

## Remaining verification before production

The container's Chromium browser blocks direct navigation to hosted and local URLs with `ERR_BLOCKED_BY_ADMINISTRATOR`, so the isolated browser checks loaded the real page HTML, stylesheet and script into a controlled document instead of performing full server navigation. A staging-site smoke test should confirm real HTTP routing, CDN and asset availability, authenticated Supabase sync under production RLS, hosted browser sign-in redirects including deep links, and the preexisting administrator-role test. No deployment was performed.
