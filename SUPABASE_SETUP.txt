The source package has a Supabase project URL and publishable browser key in assets/supabase-config.js. Existing auth account support is preserved, but course_progress, quiz_results and certificates were not present in the connected project when inspected. Local lessons, quizzes, reference search and progress work without these tables.

To activate CLOUD progress, review and run the included supabase_setup.sql in the SQL Editor of the specific Supabase project configured in assets/supabase-config.js. The revised script affects only learning-specific objects; it does not replace auth.users triggers, library tables or portfolio content. It enables row-level security for learner-owned rows.

Add your learning site’s exact /auth.html URL to Authentication > URL Configuration > Redirect URLs. Keep the current Site URL if this project is shared with the portfolio and scanner. The default confirmation-email flow needs functional email delivery (configure SMTP for production when appropriate).

To activate QR completion-record verification, expose the api schema in Supabase Data API settings. The verification endpoint returns a limited public view for an exact ID. A self-reported course-completion record is not an accredited credential.

Never publish a service_role key. The browser publishable key is expected to be public. Do not run an old SQL script that replaces a global auth.users trigger in a shared Supabase project.
