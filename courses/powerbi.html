Power BI Foundations & Interface

Understand how Power BI works before building anything.

Beginner

1. What Power BI Is

  • Power BI Desktop is used to build data models and reports.
  • Power BI Service is used to publish, share, refresh, and collaborate.
  • A report contains pages and visuals; a dashboard in the Service is a different object built from pinned tiles.
  • The normal workflow is Source → Power Query → Model → DAX → Visuals → Publish.

2. Main Desktop Areas

  • Home ribbon for data connections and common actions.
  • Report view for designing report pages.
  • Model view for relationships and model structure.
  • Data/Table view for inspecting loaded tables.
  • Fields/Data pane, Filters pane, Visualizations/Build pane.

3. Files and Saving

  • .pbix is the standard Power BI Desktop report file.
  • Save versions during learning so mistakes are reversible.
  • Understand that importing data stores model data inside the PBIX.
  • Keep source files in a stable folder if they will be refreshed later.

4. First Visual

  • Load a simple Excel table.
  • Create a Card using Revenue.
  • Create a bar chart using Region and Revenue.
  • Change a visual title.
  • Save the report.

🎯 Week Goal

Open Power BI confidently, understand the main views, and know the journey from source data to a report.

🧪 Weekly Practice

  1. Install/open Power BI Desktop.
  2. Create a blank PBIX named PowerBI_Practice.pbix.
  3. Load one simple Excel sales table.
  4. Create one Card and one bar chart.
  5. Save, close, and reopen the file.

💡 Teaching Tip

Do not rush into DAX. First learn how data moves through Power BI.

Power Query for Data Cleaning

Prepare messy source data before it reaches the model.

Data Preparation

1. Power Query Editor

  • Open with Transform Data.
  • Queries appear on the left; Applied Steps appear on the right.
  • Each transformation creates a step.
  • Power Query changes the imported result, not the original Excel/CSV source file.

2. Core Cleaning Operations

  • Remove unwanted rows and columns.
  • Rename columns clearly.
  • Change data types.
  • Replace values.
  • Trim and clean text.
  • Remove duplicates only when logically correct.

3. Shape Data

  • Split columns by delimiter.
  • Merge columns when necessary.
  • Add conditional columns.
  • Fill down or fill up when source structure requires it.
  • Filter rows before loading unnecessary records.

4. Close & Apply

  • Close & Apply loads the transformed result into the model.
  • Changing an earlier step can affect later steps.
  • Refresh reruns the query steps against the source.

🎯 Week Goal

Use Power Query to clean and shape data with repeatable transformation steps.

🧪 Weekly Practice

  1. Load a messy CSV or Excel table.
  2. Remove two unnecessary columns.
  3. Correct Date and Currency data types.
  4. Trim a text column.
  5. Replace inconsistent region names.
  6. Close & Apply and check the model.

💡 Teaching Tip

Always inspect data types. Wrong types are a common cause of broken DAX, relationships, and date analysis.

Data Modeling & Star Schema

Build a model that is easy to calculate, filter, and maintain.

Modeling

1. Fact vs Dimension

  • Fact tables contain transactions or events.
  • Dimension tables describe entities such as Date, Product, Customer, Region.
  • Facts usually contain numeric measures and foreign keys.
  • Dimensions should have a unique key for each member.

2. Star Schema

  • Place the fact table in the centre.
  • Connect dimensions around it.
  • Prefer one-to-many relationships from dimension to fact.
  • Avoid unnecessary dimension-to-dimension chains for beginner models.

3. Relationship Concepts

  • Cardinality: one-to-many, one-to-one, many-to-many.
  • Filter direction controls how filters propagate.
  • Active relationships are used by default.
  • Keys must have matching data types.

4. Model Hygiene

  • Hide technical key columns from report users when appropriate.
  • Use friendly table/column names.
  • Set default summarization appropriately.
  • Organize measures separately when the model grows.

🎯 Week Goal

Understand fact tables, dimension tables, keys, and one-to-many relationships.

🧪 Weekly Practice

  1. Create DimProduct, DimRegion and FactSales from a flat dataset.
  2. Create a unique key in each dimension.
  3. Relate each dimension one-to-many to FactSales.
  4. Check Model view for a clean star shape.
  5. Create a visual to test filter propagation.

If you cannot explain why two tables are related, do not create the relationship yet.

DAX Measures & Core Calculations

Create business metrics that respond to report filters.

DAX

1. Measures vs Columns

  • Calculated columns are computed row by row and stored in the model.
  • Measures are calculated at query time based on filter context.
  • Most report KPIs should be measures.
  • Use explicit measures instead of relying only on implicit visual sums.

2. Basic Measures

  • SUM, COUNTROWS, DISTINCTCOUNT, DIVIDE.
  • Revenue, Cost, Profit, Orders, Customers.
  • Use meaningful names and consistent formatting.

3. CALCULATE

  • CALCULATE evaluates an expression under modified filter context.
  • It is central to DAX.
  • Simple filters can be applied inside CALCULATE.
  • Later time-intelligence measures rely heavily on CALCULATE.

4. Filter Context

  • Slicers create filter context.
  • Rows/columns in a visual create filter context.
  • Measures recalculate for each context.
  • The same Total Revenue measure can show a grand total, regional total, or product total.

🎯 Week Goal
