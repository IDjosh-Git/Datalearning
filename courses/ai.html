Why learn AI for analysis?

AI can reduce drafting and troubleshooting time, surface alternatives and make complex tooling easier to learn. The value is improved speed and clearer decisions without compromising accuracy, confidentiality or professional judgement. Course exercises require you to independently execute and verify generated work.

Prerequisites: basic spreadsheet literacy, an understanding of tables and a willingness to practise. SQL, Python and DAX examples can be attempted progressively. Use the shared practice files in downloads.

WEEK 01 / 10

AI literacy for analysts

Learning outcome: Understand generative AI, predictive ML and automation; differentiate a plausible answer from a reproducible result.

Guided lesson

An LLM predicts useful text; it is not a database, calculator or guaranteed source of truth. Distinguish retrieval, inference and tool execution. Use AI for drafting plans, code, explanations and documentation; use actual data engines to calculate.

Practical lab

Map a monthly sales report: identify tasks suitable for AI assistance and tasks requiring deterministic calculation.

AI prompt to practise

Ask an AI assistant to create an analysis plan for retail_orders.csv. Request assumptions, required columns, potential bias and independent checks.

Verification and quality control

Classify an AI-generated revenue number as unverified until reconciled against source transactions.

Learning workflow

  2. Draft an AI prompt specifying tools and constraints.
  3. Review the generated plan or code.
  4. Execute using a deterministic analytics tool.
  5. Reconcile results against source records.

Prompt engineering and analytical questions

Learning outcome: Write prompts with business context, data schema, task, constraints, outputs and tests.

Guided lesson

A strong analytical prompt defines the metric (e.g. net revenue after returns), granularity, date range, exclusions, expected output and validation criteria. Demand clarification rather than guessed columns. Iterate with feedback and test cases.

WEEK 08 / 10

Statistical reasoning, ML and forecasting

Learning outcome: Understand when to use regression, clustering, forecasts and anomaly detection.

Guided lesson

Separate descriptive analysis from inference. Review train/test leakage, baselines, confidence intervals, MAE/RMSE, precision/recall, class imbalance and drift. An LLM can explain methods and draft code but statistical evidence must come from calculations.

Practical lab

Create a time-ordered demand forecast baseline using retail_orders.csv; compare naive and moving-average forecasts.

AI prompt to practise

Request a model evaluation plan with no leakage. Ask the assistant to explain whether regression assumptions are met.

Verification and quality control

Report baseline, holdout period, error metric and limitations. No causal claims from correlation.

WEEK 09 / 10

Automation, agents and workflow efficiency

Learning outcome: Design repeatable AI-supported workflows with explicit approval gates.

Guided lesson

Connect ingestion → schema check → cleaning → deterministic metrics → AI narrative draft → QA → publish. Use scheduled jobs, logging, retries, cost limits and human review. Treat retrieved pages, files and tool outputs as untrusted instructions. Quantify efficiency using timed baselines and QA outcomes.

Practical lab

Build a weekly reporting runbook and compare manual versus AI-assisted time, error rate and revisions.

AI prompt to practise

Write a step-by-step pseudocode workflow with input checks, restricted-data handling, prompt version, reviewer approval and rollback.

Verification and quality control

Calculate time saved = baseline minutes − assisted minutes; efficiency gain % = time saved / baseline × 100.
