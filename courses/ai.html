MASTERCLASS / MODULE 01 · AI for Data Analytics

AI literacy, analytics tasks and limits

By the end, you can: Separate language generation from verifiable computation.

01 · The business reason — why this matters

Analysts can use AI to outline hypotheses and draft code quickly, but confident prose is not evidence that a number is correct.

02 · How it actually works

Large language models predict plausible next tokens. External tools or an actual dataset engine are required for reproducible computation; prompt instructions alone do not grant access to the data. Distinguish summarization, retrieval, predictive modelling and deterministic SQL.

Learn it step by step — simple explanation

Picture it this way: An AI assistant predicts useful language, not the truth of a calculation. Think of it as a drafting partner whose output needs a separate evidence trail.

Follow the logic in three small steps
  1. State the analytics task and available data
  2. Ask the assistant to describe a reproducible method
  3. Run that method in Excel, SQL or Python before trusting the number
Read the expected result: 578000 completed revenue is verified by the supplied data and scripts; it is not verified merely because an AI response mentions it.
Now try it without copying: Write one prompt asking for an analysis plan and another asking for a calculated answer; label which claims need execution.

Prompt: 'Plan an analysis of mastery_orders.csv.
Identify the target KPI, required columns, risky assumptions,
and validation steps. Do not invent sales totals.'
Expected result / verification
Expected response outline: business question → columns → inclusion rule → reproducible calculation → validation. Verified completed revenue = 578000 by separate code, not by prose alone.

MASTERCLASS / MODULE 02 · AI for Data Analytics

Prompt engineering as a mini specification

By the end, you can: Ask for testable and bounded analysis outputs.

01 · The business reason — why this matters

A vague prompt such as "analyse my sales" produces generic prose, whereas a specification defines the business question and acceptance tests.

02 · How it actually works

An effective prompt contains role, objective, input schema, inclusion/exclusion rules, output format and independent checks. Use small few-shot examples for complicated labelling; iteration should reduce ambiguity, not replace testing.

Learn it step by step — simple explanation

Picture it this way: A good prompt functions like a mini requirements document. Without table names, business definitions and output constraints, the assistant must guess.

Follow the logic in three small steps
  1. Give the exact schema and grain
  2. Define which statuses count as sales
  3. Request the output format plus independent tests and edge cases
Read the expected result: A correct SQL draft filters Completed before grouping by region. AI-generated code that invents nonexistent columns must be rejected rather than silently adapted.
Now try it without copying: Rewrite a vague 'show me sales' prompt into a testable specification for regional completed revenue.
03 · Worked example
Prompt: 'Act as a retail analyst. Given fields order_id,
status, quantity, unit_price and region, draft SQLite SQL
that sums quantity*unit_price only when status=Completed.
Return SQL, expected columns, and a reconciliation query.
Use no invented columns or values.'
Expected result / verification
Expected SQL structure: WHERE status='Completed'; SUM(quantity*unit_price); GROUP BY region. Verified groups: East 316000, West 190000, North 72000.
💡 Industry pro tip

Treat acceptance criteria like software tests: expected columns, allowed tables and result reconciliation.

⚠️ Common beginner trap

Without specifying SQL dialect, AI may suggest unsupported DATE_TRUNC or TOP syntax for SQLite.

MASTERCLASS / MODULE 03 · AI for Data Analytics

Privacy, safety and responsible AI

By the end, you can: Choose what can be shared with an AI service.

01 · The business reason — why this matters

Customers, employee records and proprietary transactions may be confidential; disclosure must follow organizational policy and law.

02 · How it actually works

Classify data by sensitivity, mask or aggregate identifiers, review provider retention/settings and workspace access rules, and keep confidential datasets in approved environments. Human review is needed for bias, erroneous inferences and disclosure risk.

Learn it step by step — simple explanation

Picture it this way: Data minimization means sharing only what is necessary. Synthetic practice records are safe for exercises; real people, credentials or protected records require authorization and controls.

Follow the logic in three small steps
  1. Classify each field by sensitivity
  2. Replace personal identifiers with approved aggregates when possible
  3. Review vendor retention, sharing permissions and organization policy
Read the expected result: The fictional dataset can be used for demonstrations; a real customer list or patient record cannot automatically be uploaded to external AI tools.
Now try it without copying: Produce a safe three-column aggregate (region, completed_orders, revenue) without customer names.

Learn it step by step — simple explanation
