# Current styling architecture — 1 November 2026

## Authoritative theme

`assets/styles/design-system.css` is the **only shared site-wide presentation layer**. It is linked **once on all 38 HTML pages** and remains the final stylesheet on public/course pages. On the three protected administration pages, the deliberately scoped `admin-workspace.css` loads after it to provide the light administration skin without affecting public pages. All public learner headers use the same navy/indigo/dark-slate style and the shared `public-navigation.js` navigation controller.

- Core colours: ink navy `#15243A`, indigo `#3F46D9`, dark-slate accent `#29476B`, canvas `#F5F7FB`, white `#FFFFFF`.
- Typography: Inter with system-sans fallbacks; there are no older DM Sans/Manrope network imports.
- Keep the page-specific layout bundles where they are used: they contain route- and module-specific structure, lesson video/editor arrangement, masteries, quizzes, cards, tables, and authentication UI.
- `assets/styles/course-page-improvements.css` holds interactive course layout/assessment styles, with its original green visual accents migrated to the dark-slate and neutral theme tokens.
- `assets/styles/course-guide-pages.css` supports the lightweight roadmap/extension pages.
- `assets/styles/access-guard.css` contains necessary protected-page layout, not a public theme.

## Removed obsolete layers

The files `site-refresh.css`, `experience.css`, and `layout-tuning.css` were removed from source and from all HTML page references. Their **functional** teaching-table, icons, accessibility, and Practice Arena sizing/collapse rules were retained in the current design-system stylesheet. The old green visual scheme, decorative gradient styling, font imports, and duplicate theme layers were not retained as new global layers.

The JavaScript `assets/scripts/experience.js` remains; it provides learning enhancements and is not an obsolete stylesheet.

## Rules for future changes

1. Make shared typography, colours, header, buttons, cards, and contrast changes in `design-system.css`, not in a new appended override stylesheet.
2. Change a page-specific stylesheet only for its structural/layout behaviour. Prefer the shared `--ui-*` tokens over literal colours.
3. Preserve the unboxed “Open Practice Studio” text links, black Contact Support button, public browsing rules, and account/admin security.
4. Maintain a single public header and avoid adding duplicate navigation initializers.
5. Run `npm run verify:deployment` after edits, including the `modern-style-architecture.mjs` regression test.

## Test status and limitation

The full build, JavaScript lint, site integrity, CSS top-level syntax, navigation, mobile source checks, auth/admin, course-learning, tutor, and Practice Arena suites pass. Static colour pairs are checked in `tests/public-theme-contrast.mjs`. These tests do not replace visual browser or assistive-technology audits. Headless Chromium did not produce a usable screenshot in this environment; check the rendered site at 390px, 768px, and 1440px before production promotion.

## Remaining route CSS review (1 November 2026)

Fifteen remaining routes and 20 route stylesheets were audited for unused selectors, repeated rules and obsolete visual accent colours. Public routes continue to load `design-system.css` last; protected administration pages load the scoped `admin-workspace.css` afterward. Maintain route files for their functional layouts only; do not reintroduce a second global theme. The audit inventory and validation notes are in `REMAINING_PAGE_STYLE_AUDIT.md`.

## Protected administration workspace styling (November 2026)

`assets/styles/admin-workspace.css` is the single maintained light skin for `admin.html`, `progress.html`, and `reviewer.html`. The three pages have only one administrator sidebar/topbar generated by `admin-console.js`; old static navigation/header/footer duplicates have been physically removed. The new admin stylesheet is served through the existing admin-asset middleware guard. Do not move it to the public shared stylesheet, remove its access restriction, or reintroduce old `.ac-*` styling into the three page-specific CSS files. See `docs/ADMIN_WORKSPACE_THEME_AUDIT.md`.

## Current mobile and workspace styling (1 November 2026)

The learner account welcome area and protected administrator workspace now both use light page surfaces. Edit `account.css` for the former and `admin-workspace.css` for the latter; `design-system.css` owns the shared phone/tablet grid and overflow corrections. See [Responsive and light-workspace audit](RESPONSIVE_AND_LIGHT_THEME_AUDIT.md). Functional dialog/drawer scrims and intentionally dark public mastheads/footer are not dark mode.
